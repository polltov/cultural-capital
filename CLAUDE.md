## Выкладка на боевой сайт — делать самому

Владелец просит доводить работу до боевого сайта самостоятельно, не спрашивая отдельного разрешения: после проверок (`tsc`, `lint`, юнит- и интеграционные тесты, `next build`) слить PR в `main`, дождаться выкладки, затем открыть боевой адрес и убедиться, что новая версия на месте.

- Сайт работает на сервере в Селектеле (README, «Где работает сайт»). Адрес — `https://culturaltours.ru` (`SITE_URL` в `app.env` на сервере; README, «Домен»).
- Слияние в `main` само выкладывает сайт: GitHub Actions `Deploy` (`.github/workflows/deploy.yml`) собирает образ сайта и передаёт его на сервер вместе с кодом, там `deploy/deploy.sh` применяет миграции из `drizzle/`, перезапускает сайт и обновляет публичные страницы. Адреса, которые попадают в образ, — в `deploy/build.env` (совпадают с `app.env` на сервере). Следить за запуском через GitHub (список запусков и журнал задания); выложить `main` повторно — запуском workflow `deploy.yml` вручную. SSH к серверу у облачной сессии нет: всё через этот workflow.
- Если запуск пропущен с пометкой «Сервер в Селектеле ещё не подключён» — переезд не закончен (README, «Сервер в Селектеле»): сказать владельцу, что выкладывать пока некуда, и какие шаги остались.
- Миграции применяются до перезапуска, пока работает старая версия сайта: схему базы менять только добавлением, чтобы старая версия не ломалась.
- На Vercel новые версии не выкладывать: до переезда там работает старая версия сайта, после — только перенаправление на новый домен (README, «Переезд данных с Vercel», шаг 3). Для этого шага нужен токен Vercel в сетевых секретах среды `cultural-capital` для `api.vercel.com` (CLI запускается с любым `--token`, настоящий подставляет прокси); если токена нет, не просить его в чате, а попросить владельца добавить его в настройках среды.
- Чтобы проверить боевой сайт, домен `culturaltours.ru` должен быть открыт в сетевых настройках среды `cultural-capital`; если его там нет — предложить добавить.
