# Культурная Столица

Сайт экскурсионного проекта «Культурная Столица» (экскурсии по Петербургу для детей и взрослых) с админ-панелью: каталог экскурсий и сеансов, онлайн-продажа билетов с оплатой через ЮKassa (с уведомлением об оплаченных заказах в Telegram), новости, список участников сеанса с печатью и выгрузкой в CSV.

Стек: Next.js 16 (App Router), TypeScript, Drizzle ORM + стандартный Postgres, Vercel Blob (обложки), ЮKassa (онлайн-оплата), Resend (письма с билетом), Vitest.

## Локальная разработка

1. Поднять Postgres:

   ```bash
   docker compose -f docker-compose.test.yml up -d
   ```

   Контейнер слушает порт 54329; базы `dev` (для `npm run dev`) и `test` (для интеграционных тестов).

2. Создать `.env.local` из шаблона и заполнить значения:

   ```bash
   cp .env.example .env.local
   ```

   Важно: Next раскрывает `$VAR` в `.env`-файлах, поэтому в `.env.local` каждый `$` в `ADMIN_PASSWORD_HASH` нужно экранировать как `\$` (кавычки не помогают), например `\$2b\$12\$...`.

3. Применить миграции и заполнить базу начальными данными:

   ```bash
   npm install
   npm run db:migrate
   npm run db:seed
   npm run dev
   ```

   Сайт: http://localhost:3000, админка: http://localhost:3000/admin.

## Переменные окружения

| Переменная | Назначение |
| --- | --- |
| `DATABASE_URL` | строка подключения к Postgres |
| `BLOB_READ_WRITE_TOKEN` | токен Vercel Blob (загрузка обложек) |
| `ADMIN_LOGIN` | логин администратора |
| `ADMIN_PASSWORD_HASH` | bcrypt-хеш пароля администратора |
| `SESSION_SECRET` | секрет подписи сессии (случайные 32 байта) |
| `TELEGRAM_BOT_TOKEN` | токен бота для уведомлений об оплаченных заказах |
| `TELEGRAM_CHAT_ID` | чат, куда приходят уведомления |
| `SITE_URL` | публичный адрес сайта: Open Graph, ссылки в уведомлениях, `return_url` оплаты и ссылки в письмах (на проде — собственный домен) |
| `YOOKASSA_SHOP_ID` | идентификатор магазина ЮKassa (для разработки — тестового) |
| `YOOKASSA_SECRET_KEY` | секретный ключ магазина ЮKassa |
| `YOOKASSA_VAT_CODE` | код ставки НДС в чеках; по умолчанию `1` («без НДС») |
| `RECEIPT_CLOSING` | `on` — ночная задача выбивает закрывающий чек после экскурсии; по умолчанию `off` |
| `RESEND_API_KEY` | ключ Resend для писем с билетом (на Vercel ставится интеграцией Marketplace) |
| `MAIL_FROM` | отправитель писем, адрес на домене, подтверждённом в Resend |
| `CRON_SECRET` | секрет ночной задачи `/api/cron/nightly` |

## Онлайн-оплата

Билет покупается на сайте: оплата через ЮKassa (виджет на странице), билет и кассовый чек приходят на email. Запросы к ЮKassa, Resend и Telegram идут напрямую через `fetch`, без SDK.

- **Тестовый магазин.** Для разработки и превью-деплоев задайте `YOOKASSA_SHOP_ID` и `YOOKASSA_SECRET_KEY` **тестового** магазина ЮKassa (тестовые карты и тестовый СБП). Боевые ключи ставятся в Production только когда домен привязан к проекту Vercel и подтверждён в Resend.
- **Уведомления ЮKassa.** В кабинете ЮKassa укажите URL уведомлений `https://<домен>/api/payments/yookassa` и включите события `payment.succeeded`, `payment.canceled`, `refund.succeeded`.
- **Возврат в кабинете ЮKassa.** Если «Отменить и вернуть» в админке не проходит, оформите возврат в кабинете ЮKassa. Сайт сам увидит его — по уведомлению `refund.succeeded`, при повторном нажатии «Отменить и вернуть» или ночью перед закрывающим чеком — и отменит заказ с фактически возвращённой суммой; второго возврата не будет.
- **Ночная задача.** Vercel Cron вызывает `/api/cron/nightly` раз в сутки в 00:00 UTC (03:00 по Москве); расписание лежит в `vercel.ts`. Запрос защищён `CRON_SECRET`: Vercel передаёт его заголовком `Authorization: Bearer <секрет>`, без секрета роут отвечает 401. Задача подбирает оплаты, чьи уведомления потерялись, переводит просроченные заказы в `expired`, а прошедшие экскурсии — в `done` (и при `RECEIPT_CLOSING=on` выбивает закрывающие чеки). Вручную: `curl -H "Authorization: Bearer $CRON_SECRET" <SITE_URL>/api/cron/nightly`.
- **`SITE_URL`** должен указывать на реальный домен сайта: от него зависят `return_url` после оплаты и ссылки в письмах.
- **Закрывающий чек.** Включите `RECEIPT_CLOSING` (если бухгалтер подтвердит схему с закрывающим чеком) до первых реальных продаж — если включить позже, ночная задача выбьет закрывающие чеки по всем прошлым проведённым заказам. Ставку НДС (`YOOKASSA_VAT_CODE`) тоже подтверждает бухгалтер.

## Как сменить пароль администратора

1. Сгенерировать хеш (пароль вводится без эха):

   ```bash
   npx tsx scripts/hash-password.ts
   ```

2. Записать его в Vercel **без** экранирования (вставлять хеш как есть, с обычными `$`):

   ```bash
   vercel env add ADMIN_PASSWORD_HASH production
   ```

3. Выполнить новый деплой, чтобы переменная вступила в силу. Для локальной работы тот же хеш кладётся в `.env.local` с экранированием `\$`.

## Выкладка на продакшен

1. Применить миграции к боевой базе до деплоя:

   ```bash
   DATABASE_URL="<боевая строка>" npm run db:migrate
   ```

2. Выполнить сид ровно один раз (скрипт откажется работать, если в таблице `tours` уже есть данные; `--force` обходит защиту и перезапишет правки):

   ```bash
   DATABASE_URL="<боевая строка>" npm run db:seed
   ```

3. В админке добавить реальные будущие сеансы (сеансы из сида — демонстрационные, их даты в прошлом).
4. Заменить текст страницы `/privacy` на актуальную политику обработки персональных данных.
5. Проверить, что в окружении Vercel заданы все переменные из таблицы выше, затем выкатить: `vercel deploy --prod`.

Конфигурация проекта на Vercel лежит в `vercel.ts` (фреймворк Next.js, регион `fra1`).

## Перенос базы данных к другому провайдеру

Приложение использует только `DATABASE_URL` и стандартный Postgres, никаких специфичных API провайдера. Для переезда (например, на российский хостинг):

1. Создать новую базу Postgres и получить строку подключения.
2. Применить схему: `DATABASE_URL="<новая>" npm run db:migrate`.
3. Скопировать данные: `pg_dump --data-only --no-owner "<старая>" | psql "<новая>"` (затем при необходимости выровнять последовательности через `setval`).
4. Заменить `DATABASE_URL` в окружении Vercel и выполнить новый деплой.
