# Культурная Столица

Сайт экскурсионного проекта «Культурная Столица» (экскурсии по Петербургу для детей и взрослых) с админ-панелью: каталог экскурсий и сеансов, онлайн-продажа билетов с оплатой через ЮKassa (с уведомлением об оплаченных заказах в Telegram), новости, список участников сеанса с печатью и выгрузкой в CSV, отметка прихода по QR-коду билета.

Стек: Next.js 16 (App Router), TypeScript, Drizzle ORM + стандартный Postgres, Vercel Blob (обложки), ЮKassa (онлайн-оплата), Resend (письма с билетом), Vitest.

## Публичный сайт

| Адрес | Что там |
| --- | --- |
| `/` | первый экран с ближайшей экскурсией, каталог, ближайшие даты, «О нас», как проходит экскурсия, отзывы, индивидуальные экскурсии, новости, вопросы |
| `/tours/<адрес>` | страница экскурсии: описание, маршрут, место встречи, что взять, условия, выбор даты и покупка, другие экскурсии |
| `/afisha` | все будущие сеансы по месяцам с покупкой в один клик |
| `/news`, `/news/<адрес>` | новости |
| `/order/<токен>` | билет после оплаты (по секретной ссылке, не индексируется) |
| `/offer`, `/privacy`, `/consent` | документы |

Всё про экскурсии (тексты, фото, цены, даты, место встречи и «что взять с собой») редактируется в админке; главная, афиша и страницы экскурсий обновляются сразу после сохранения и после каждой покупки. Для поисковиков есть `sitemap.xml`, `robots.txt` и микроразметка schema.org (экскурсии и их сеансы, организация, хлебные крошки). Ссылка на экскурсию в Telegram и ВКонтакте показывает собственную картинку-превью: название, подзаголовок, маршрут и обложка экскурсии в фирменном стиле (`src/app/(site)/tours/[slug]/opengraph-image.tsx`, шрифты и логотип для неё — в `src/assets/og/`).

- **Контакты.** Кнопка «Написать», блок индивидуальных экскурсий, контакты в меню, в вопросах и в подвале появляются, только когда заполнено, куда писать: Telegram, WhatsApp и ВКонтакте — в `src/lib/contacts.ts`, телефон и почта — в реквизитах `src/lib/legal.ts`. Пока всё пусто, этих кнопок нет.
- **Обложки экскурсий.** Фото загружается в админке; на сайт оно уходит уменьшенной копией под экран. Лучше горизонтальное фото от 1600 px по ширине. Пока фото нет, вместо него — фирменная гравюра с атлантами на цветной подложке.
- **Логотип.** `public/brand/` — векторные копии логотипа (знак, надпись, орнамент «•—✳—•»), иконка для iOS и картинка для превью ссылок `og.jpg` (1200×630); исходники — PNG в `public/assets/`. Иконка вкладки (`favicon.svg`, PNG 32 и 120 px, `public/favicon.ico`) — упрощённый портал с логотипа на терракоте: гравюра в 16 px не читается; подключается в `src/lib/site-icons.ts`.
- **Шрифты.** Лежат в `public/fonts/` и подключаются в `src/app/fonts.css` (Prata — заголовки, Playfair Display — курсивные акценты, PT Serif — текст, PT Sans — интерфейс; все под SIL Open Font License). Там же — запасные системные шрифты, подогнанные по ширине, чтобы страница не «прыгала» при загрузке. Цифры в заголовочном шрифте взяты из Playfair Display (у Prata единица неотличима от «l»): файл `prata-digits-*.woff2` и цифры в `src/assets/og/Prata-Regular.ttf` собирает `python scripts/fonts/prata-digits.py` (нужны `fonttools` и `brotli`).
- **Анимации.** Переходы между страницами — `src/components/site/transitions.tsx` (React `<ViewTransition>`): из каталога обложка карточки перетекает в обложку страницы экскурсии, переходы «вглубь» и «назад» сдвигают страницу, шапка стоит на месте. Движение на странице (появление при прокрутке, вход первого экрана, раскрытие вопросов) — CSS в `site.css`, раздел 26. Всё отключается системной настройкой «уменьшить движение»; браузеры без поддержки просто показывают страницы без анимации.

## Отметка прихода по QR-коду

На билете (страница заказа, печать, письма с билетом и напоминанием) есть QR-код. Он ведёт на `/admin/checkin/<токен заказа>`: гид сканирует его обычной камерой телефона, на котором вошёл в админку, видит, чей это билет, на какой сеанс и сколько человек, и нажимает «Отметить приход». Если гид ещё не вошёл, после входа его вернёт на эту же страницу. Отметки видны и ставятся вручную в списке участников сеанса (колонка «Пришли»), попадают в CSV. QR-код показывается только у оплаченного заказа; у отменённого картинка в старом письме пропадает.

## Локальная разработка

1. Поднять Postgres:

   ```bash
   docker compose -f docker-compose.test.yml up -d
   ```

   Контейнер слушает порт 54329; базы `dev` (для `npm run dev`) и `test` (для интеграционных тестов).

2. Создать `.env.local` из шаблона и заполнить значения:

   ```bash
   cp .env.example .env.local
   ```

   Важно: Next раскрывает `$VAR` в `.env`-файлах, поэтому в `.env.local` каждый `$` в `ADMIN_PASSWORD_HASH` нужно экранировать как `\$` (кавычки не помогают), например `\$2b\$12\$...`.

3. Применить миграции и заполнить базу начальными данными:

   ```bash
   npm install
   npm run db:migrate
   npm run db:seed
   npm run dev
   ```

   Сайт: http://localhost:3000, админка: http://localhost:3000/admin.

## Онлайн-оплата

Билет покупается на сайте: оплата через ЮKassa (виджет на странице), билет и кассовый чек приходят на email. Запросы к ЮKassa, Resend и Telegram идут напрямую через `fetch`, без SDK.

- **Тестовый магазин.** Для разработки и превью-деплоев задайте `YOOKASSA_SHOP_ID` и `YOOKASSA_SECRET_KEY` **тестового** магазина ЮKassa (тестовые карты и тестовый СБП). Боевые ключи ставятся в Production только когда домен привязан к проекту Vercel и подтверждён в Resend.
- **Уведомления ЮKassa.** В кабинете ЮKassa укажите URL уведомлений `https://<домен>/api/payments/yookassa` и включите события `payment.succeeded`, `payment.canceled`, `refund.succeeded`.
- **Отмена части билетов.** В карточке оплаченного заказа «Отменить часть билетов»: сколько детских и взрослых отменить и сумма возврата (по правилу 24 ч / 50% от стоимости этих билетов, редактируется). Места освобождаются сразу, остальные билеты действуют, клиенту уходит письмо. Возвратов по заказу может быть несколько; сумма заказа остаётся суммой платежа, возвращённое копится, история видна в карточке. «Отменить и вернуть» после частичных отмен предлагает не больше невозвращённого остатка. При `RECEIPT_CLOSING=on` закрывающий чек по заказу с частичной отменой автоматически не выбивается (сумма остатка не равна стоимости оставшихся билетов) — придёт тревога, чек оформляется в кабинете ЮKassa.
- **Возврат в кабинете ЮKassa.** Если «Отменить и вернуть» в админке не проходит, оформите возврат в кабинете ЮKassa. Сайт сам увидит его — по уведомлению `refund.succeeded`, при повторном нажатии «Отменить и вернуть» или ночью перед закрывающим чеком — и отменит заказ с фактически возвращённой суммой; второго возврата не будет.
- **Ночная задача.** Vercel Cron вызывает `/api/cron/nightly` раз в сутки в 00:00 UTC (03:00 по Москве); расписание лежит в `vercel.ts`. Запрос защищён `CRON_SECRET`: Vercel передаёт его заголовком `Authorization: Bearer <секрет>`, без секрета роут отвечает 401. Задача подбирает оплаты, чьи уведомления потерялись, переводит просроченные заказы в `expired`, а прошедшие экскурсии — в `done` (и при `RECEIPT_CLOSING=on` выбивает закрывающие чеки). Если что-то по заказам не удалось, в Telegram приходит тревога с числом ошибок (подробности — в логах Vercel). Вручную: `curl -H "Authorization: Bearer $CRON_SECRET" <SITE_URL>/api/cron/nightly`.
- **Дневная задача.** `/api/cron/daily` — раз в сутки в 15:00 UTC (18:00 по Москве), защищена тем же `CRON_SECRET`. Шлёт напоминание об экскурсии всем оплаченным заказам на сеансы до конца завтрашнего дня (кроме купивших меньше 6 часов назад; после переноса на другой сеанс напоминание уйдёт заново). При `ABANDONED_MAIL=on` ещё шлёт «вы не завершили оплату» по неоплаченным заказам за последние 3 дня, если на ту же дату хватает мест, экскурсия не раньше чем через 3 часа, а покупатель после этого не оформлял новых заказов; одному адресу — не чаще раза в 14 дней. Если письма не ушли, в Telegram приходит тревога.
- **`SITE_URL`** должен указывать на реальный домен сайта: от него зависят ссылки в письмах (билет, каталог) и в Telegram. Адрес, куда ЮKassa возвращает покупателя после оплаты (`return_url`), от `SITE_URL` не зависит: виджет берёт адрес страницы, на которой его открыли. Схему и слеш в конце сайт допишет и уберёт сам (`kc.example` → `https://kc.example`).
- **Закрывающий чек.** Включите `RECEIPT_CLOSING` (если бухгалтер подтвердит схему с закрывающим чеком) до первых реальных продаж — если включить позже, ночная задача выбьет закрывающие чеки по всем прошлым проведённым заказам. Ставку НДС (`YOOKASSA_VAT_CODE`) тоже подтверждает бухгалтер.

## Сотрудники

Владелец входит в админку логином и паролем из переменных `ADMIN_LOGIN` и `ADMIN_PASSWORD_HASH`. Остальным владелец (или администратор) заводит личные учётки в разделе «Сотрудники» (`/admin/users`):

- **Администратор** видит и делает всё: заказы, возвраты, экскурсии, новости, вопросы, сотрудники.
- **Гид** видит только сводку ближайших сеансов, списки участников (с печатью и CSV) и отметку прихода по QR-коду.

Смена пароля, роли или отключение входа сразу выкидывают сотрудника из админки на всех устройствах. Себе нельзя сменить роль или отключить вход. Смена пароля владельца в Vercel тоже завершает все его сессии.

## Как сменить пароль владельца

1. Сгенерировать хеш (пароль вводится без эха):

   ```bash
   npx tsx scripts/hash-password.ts
   ```

2. Записать его в Vercel **без** экранирования (вставлять хеш как есть, с обычными `$`):

   ```bash
   vercel env add ADMIN_PASSWORD_HASH production
   ```

3. Выполнить новый деплой, чтобы переменная вступила в силу. Для локальной работы тот же хеш кладётся в `.env.local` с экранированием `\$`.

## Выкладка на продакшен

1. Применить миграции к боевой базе до деплоя:

   ```bash
   DATABASE_URL="<боевая строка>" npm run db:migrate
   ```

2. Выполнить сид ровно один раз (скрипт откажется работать, если в таблице `tours` уже есть данные; `--force` обходит защиту и перезапишет правки):

   ```bash
   DATABASE_URL="<боевая строка>" npm run db:seed
   ```

3. В админке добавить реальные будущие сеансы (сеансы из сида — демонстрационные, их даты в прошлом).
4. Заменить текст страницы `/privacy` на актуальную политику обработки персональных данных.
5. Проверить, что в окружении Vercel заданы все переменные из таблицы выше, затем выкатить: `vercel deploy --prod`.

Конфигурация проекта на Vercel лежит в `vercel.ts` (фреймворк Next.js, регион `fra1`).

## Свой домен (.рф)

Сейчас сайт работает на `cultural-capital.vercel.app`. Переезд на собственный домен делается в настройках, код менять не нужно. Ниже в примерах — `культурнаястолица.рф`.

Кириллический домен в интернете на самом деле записан латиницей, в punycode: `культурнаястолица.рф` = `xn--80aaxgfbmjpmhegc7c3esc.xn--p1ai`. Посетители видят кириллицу, а там, где сервис не принимает кириллицу (Vercel, Resend, ЮKassa, почтовые адреса), домен вводится в punycode. Перевести адрес можно в любом онлайн-конвертере punycode или командой `node -e 'console.log(new URL("https://культурнаястолица.рф").hostname)'`. В `SITE_URL` домен можно записать кириллицей: в ссылки он сам попадёт в punycode, чтобы открываться в любой почте и мессенджере.

1. **Купить домен** у регистратора, который продаёт .рф (REG.RU, RU-CENTER и другие).
2. **Добавить домен в Vercel:** проект `cultural-capital` → Settings → Domains → Add, ввести домен (если кириллицу не примет — в punycode). Vercel предложит добавить и `www`; выбрать вариант, где `www` перенаправляется на домен без `www`.
3. **Прописать DNS у регистратора:** те записи, которые Vercel покажет у домена (обычно запись `A` для самого домена и `CNAME` для `www`). Записи начинают работать в течение нескольких часов; когда Vercel увидит их, он сам выпустит HTTPS-сертификат, и у домена появится «Valid Configuration».
4. **Перенаправить старый адрес:** в том же списке доменов у `cultural-capital.vercel.app` → Edit → перенаправление на новый домен (постоянное, 308). Старые ссылки продолжат работать, а поисковики перенесут страницы на новый адрес.
5. **Сменить `SITE_URL`** в окружении Production на `https://культурнаястолица.рф` и выложить сайт заново (`vercel deploy --prod`): без новой выкладки переменная не подхватится. После этого письма, Telegram, `sitemap.xml`, `robots.txt` и превью ссылок ведут на новый домен.
6. **Почта (Resend):** добавить домен в Resend (в punycode), прописать у регистратора записи SPF и DKIM, которые покажет Resend, и задать `MAIL_FROM`, например `Культурная Столица <tickets@xn--80aaxgfbmjpmhegc7c3esc.xn--p1ai>`. В почте покупатель видит имя «Культурная Столица», адрес в punycode показывается только в подробностях письма.
7. **ЮKassa:** в кабинете магазина указать новый адрес сайта и URL уведомлений `https://xn--80aaxgfbmjpmhegc7c3esc.xn--p1ai/api/payments/yookassa`.
8. **Поисковики:** добавить новый домен в Яндекс Вебмастер и Google Search Console и отправить `https://<домен>/sitemap.xml`.
9. **Облачные сессии Claude:** заменить адрес сайта в `CLAUDE.md` и открыть новый домен в сетевых настройках среды `cultural-capital`, иначе после выкладки нельзя будет проверить боевой сайт.

## Перенос базы данных к другому провайдеру

Приложение использует только `DATABASE_URL` и стандартный Postgres, никаких специфичных API провайдера. Для переезда (например, на российский хостинг):

1. Создать новую базу Postgres и получить строку подключения.
2. Применить схему: `DATABASE_URL="<новая>" npm run db:migrate`.
3. Скопировать данные: `pg_dump --data-only --no-owner "<старая>" | psql "<новая>"` (затем при необходимости выровнять последовательности через `setval`).
4. Заменить `DATABASE_URL` в окружении Vercel и выполнить новый деплой.
