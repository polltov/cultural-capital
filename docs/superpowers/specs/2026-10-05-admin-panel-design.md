# Админ-панель «Культурной Столицы» — дизайн

Дата: 2026-10-05

## Цель

Дать команде (1–2 человека) управлять с сайта экскурсиями, новостями и заявками без правки HTML. Сейчас сайт — один статичный файл `mockups/direction-d.html` на Vercel: экскурсии зашиты в разметку, новостей нет, кнопка «Купить» ничего не делает.

Критерии успеха:
- экскурсию, её даты, цены и лимит мест можно создать/изменить в админке, и сайт обновляется сразу;
- посетитель оставляет заявку на конкретный сеанс, админ получает уведомление в Telegram и обрабатывает её в админке;
- места считаются автоматически, перепродать сеанс нельзя;
- новости публикуются на главной (3 последние), на отдельной странице и в архиве;
- админкой удобно пользоваться с телефона.

## Решения, принятые с заказчиком

| Вопрос | Решение |
|---|---|
| Заказы | Заявки без оплаты. Онлайн-оплату и онлайн-кассу (54-ФЗ) подключим позже — модель данных готовится к этому заранее |
| Пользователи | Один общий доступ по логину и паролю, без ролей |
| Уведомления | Telegram-бот в рабочий чат |
| Новости | Блок на главной + страница новости + архив |
| Места | Автоматически: лимит на сеанс минус участники подтверждённых заявок; лимит можно править вручную |
| Подход | Миграция на Next.js + собственная админка |
| БД | Neon Postgres через Vercel Marketplace. Переезд в российскую БД (152-ФЗ) — отдельной задачей позже |

## Вне рамок

Онлайн-оплата, фискализация, роли и несколько учёток, email-уведомления, переезд БД в РФ, личный кабинет клиента, редизайн публичного сайта.

## Архитектура

- **Next.js (App Router) + TypeScript**, деплой на Vercel (как сейчас).
- **Drizzle ORM** поверх стандартного Postgres-драйвера; никаких Neon-специфичных возможностей, чтобы переезд БД = смена `DATABASE_URL`.
- **Vercel Blob** — обложки экскурсий и новостей.
- **Server Actions** для всех мутаций админки. Единственный публичный эндпоинт мутации — отправка заявки (Server Action формы записи).
- Публичные страницы кешируются; после сохранения в админке вызывается `revalidatePath`/`revalidateTag`.
- Текущая вёрстка переносится 1:1 (CSS и разметка из `direction-d.html`), статичные данные заменяются данными из БД. Ассеты из `mockups/assets/` переезжают в `public/`. Старый URL `mockups/direction-d.html` редиректит на `/`.

### Маршруты

```
/                      главная
/news                  архив новостей
/news/[slug]           страница новости
/admin/login           вход
/admin                 сводка
/admin/orders          список заявок
/admin/orders/[id]     карточка заявки
/admin/tours           список экскурсий
/admin/tours/new       новая экскурсия
/admin/tours/[id]      редактирование экскурсии и её сеансов
/admin/sessions/[id]   список участников сеанса (печать / CSV)
/admin/news            список новостей
/admin/news/new        новая новость
/admin/news/[id]       редактирование новости
```

Все `/admin/*`, кроме `/admin/login`, защищены проверкой сессии (в middleware/proxy и повторно в каждом Server Action).

## Модель данных

**tours**
- `id`, `slug`, `title`, `subtitle` (t-tag), `route` (t-route), `description` (Markdown), `note`, `duration_label` («2 часа»), `age_label` («6+»), `cover_url`
- `price_child`, `price_adult` — целые рубли
- `featured` (bool), `sort_order` (int), `published` (bool), `created_at`, `updated_at`

**tour_sessions** (сеанс)
- `id`, `tour_id` → tours, `starts_at` (timestamptz, Europe/Moscow при вводе/выводе), `capacity` (int, по умолчанию 8), `hidden` (bool)
- Свободно = `capacity − Σ(children + adults)` по заявкам со статусом `confirmed` или `done`.

**orders**
- `id`, `number` (человекочитаемый, напр. `КС-0042`), `session_id` → tour_sessions
- `customer_name`, `phone` (нормализованный `+7XXXXXXXXXX`), `email` (nullable), `comment`
- `children`, `adults` (int ≥ 0, сумма ≥ 1)
- `price_child_snapshot`, `price_adult_snapshot`, `total` — слепок цен на момент заявки
- `status`: `new | confirmed | done | cancelled`
- `admin_note`, `consent_at` (время согласия на обработку ПДн)
- под оплату (пока не используются): `payment_status` (nullable), `payment_id` (nullable)
- `created_at`, `updated_at`

**news**
- `id`, `slug` (уникальный), `title`, `excerpt`, `body` (Markdown), `cover_url`, `published_at` (nullable = черновик), `created_at`, `updated_at`

### Переходы статусов заявки

```
new → confirmed → done
new → cancelled
confirmed → cancelled
```
Остальные переходы запрещены и отклоняются сервером.

Подтверждение (`new → confirmed`) выполняется в транзакции с блокировкой строки сеанса (`SELECT … FOR UPDATE`): пересчитываются свободные места; если их меньше, чем участников в заявке, действие отклоняется с сообщением «Свободно N, в заявке M — увеличьте лимит или отмените», заявка остаётся `new`. Уменьшить `capacity` ниже уже подтверждённых участников нельзя.

## Аутентификация

- `ADMIN_LOGIN` и `ADMIN_PASSWORD_HASH` (bcrypt/argon2) — переменные окружения Vercel. Таблицы пользователей нет.
- Сессия — подписанная (`SESSION_SECRET`) httpOnly, Secure, SameSite=Lax cookie, срок 30 дней.
- Ограничение попыток входа: 5 неудачных попыток с IP за 15 минут → временная блокировка (счётчик в БД).
- Выход — кнопка в меню, удаляет cookie.

## Публичный сайт

- Главная выглядит как сейчас. Каталог строится из опубликованных экскурсий по `sort_order`; бейдж «осталось N мест» показывается, когда у ближайшего сеанса свободно ≤ 4 места; «мест нет» — когда 0.
- Новый блок «Новости» (3 последние опубликованные) в стилистике сайта; ссылка «Все новости» → `/news`.
- `/news/[slug]`: обложка, дата, Markdown-текст (санитизированный), Open Graph-теги.

### Форма записи

Кнопка «Купить» → «Записаться», открывает модальное окно:
1. выбор сеанса (будущие, не скрытые; без мест — неактивны с подписью «мест нет»);
2. счётчики «Детей» / «Взрослых» с живым пересчётом суммы;
3. имя, телефон (маска +7), email (необязательно), комментарий;
4. чекбокс согласия на обработку персональных данных (обязателен) со ссылкой на политику;
5. «Отправить заявку».

Сервер: валидация (zod), honeypot-поле, лимит 5 заявок с IP в час, проверка что сеанс будущий, не скрыт и в нём есть свободные места на момент отправки (места при этом не резервируются). Успех → экран «Спасибо! Номер заявки КС-0042. Мы свяжемся с вами в ближайшее время».

### Уведомление в Telegram

После сохранения заявки — сообщение через Bot API в `TELEGRAM_CHAT_ID` (`TELEGRAM_BOT_TOKEN`): экскурсия, дата/время, состав, сумма, имя, телефон, ссылка на `/admin/orders/[id]`. Отправка не блокирует ответ клиенту (`after()`); ошибка Telegram логируется, заявка сохраняется в любом случае.

## Админка

Общий каркас: боковое меню (Сводка, Заявки, Экскурсии, Новости, Выйти); на ширине < 768px — нижняя панель вкладок. Визуальный язык сайта (Prata / PT Sans, кремовый фон, терракотовые акценты), плотнее и спокойнее. Все формы показывают ошибки валидации у полей и тост об успешном сохранении.

**Сводка:** счётчик новых заявок (ссылка на отфильтрованный список); ближайшие сеансы на 14 дней с заполненностью «5 из 8» и полоской → список участников.

**Заявки:** таблица (на телефоне — карточки): номер, дата заявки, экскурсия и сеанс, клиент, состав, сумма, статус. Фильтры: статус (по умолчанию «Новые»), экскурсия, сеанс; поиск по имени/телефону; пагинация по 30. Карточка: все данные, `tel:`-ссылка, кнопки доступных переходов статуса, заметка админа.

**Участники сеанса:** список подтверждённых заявок с составом и телефонами, итог по людям; печатная версия и экспорт CSV.

**Экскурсии:** список с перетаскиванием порядка и переключателем публикации. Форма: все поля + загрузка обложки + блок сеансов (добавить/изменить дату, время, лимит; скрыть). Сеанс с заявками удалить нельзя — только скрыть. Справа (на десктопе) — живое превью карточки-билета, использующее тот же компонент, что и сайт.

**Новости:** список (черновики и опубликованные). Форма: заголовок, slug (автогенерация транслитом, можно править), анонс, обложка (drag-and-drop), Markdown-редактор с панелью (жирный, курсив, список, ссылка) и вкладкой «Предпросмотр», «Опубликовать» / «В черновики».

## Обработка ошибок

- Ошибки валидации — у полей формы, на русском.
- Конфликт мест — понятное сообщение, состояние не меняется.
- Ошибки загрузки фото — сообщение, форма не теряет введённые данные.
- Непредвиденные ошибки — общий экран ошибки в админке, детали в логах Vercel.

## Переменные окружения

`DATABASE_URL`, `BLOB_READ_WRITE_TOKEN`, `ADMIN_LOGIN`, `ADMIN_PASSWORD_HASH`, `SESSION_SECRET`, `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`, `SITE_URL`.

## Миграция данных

Сид-скрипт переносит 4 текущие экскурсии из `direction-d.html` (названия, описания, цены, даты, фото) в БД, чтобы сайт после переезда выглядел так же.

## Тестирование

- Юнит (Vitest): подсчёт свободных мест, допустимые переходы статусов, расчёт суммы, нормализация телефона, генерация slug.
- Интеграционные (Vitest + отдельная тестовая БД): заявка → подтверждение → места уменьшились; подтверждение сверх лимита отклоняется; две параллельные попытки подтвердить последние места — проходит одна.
- Проверка в браузере: главная совпадает с текущей вёрсткой, форма записи, вход, все экраны админки на десктопе и мобильной ширине.
